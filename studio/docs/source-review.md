## 没有放入默认内核的能力

| 能力 | 原因 |
|---|---|
| 账号积分账本 | 只有来源项目 A 使用，属于领域模型 |
| 抽奖算法与概率配置 | 来源项目 A 专属业务 |
| 永久竞价排行榜 | 来源项目 B 专属业务 |
| 具体业务与法务翻译 | 当前只有来源项目 B 完整使用，内容必须按新项目重新编写 |
| 在线人数与访问统计 | 两边口径不同，应作为独立功能模块加入 |
| 法务和规则页面内容 | 与具体商品、支付和司法辖区相关，不能盲目复用 |

## 原项目暴露出的重复成本

两边的 Worker 都逐步长到近千行或超过千行。支付提供商选择、结账请求、签名校验、事件字段提取、待支付单核对、幂等、退款和业务履约混在同一文件里。模板把它们拆成以下边界：

    src/lib/payments
        提供商配置
        托管结账请求
        Webhook 验签和事件归一化

    src/domain/fulfillment.ts
        成功支付如何改变业务
        退款或争议如何撤销业务结果

    src/worker.ts
        HTTP 中间件
        公共接口
        业务路由注册

这样创建新项目时，不需要再次复制并手工改动一整份 Worker。

## 模板仍需按项目完成的事情

1. 明确用户与资源所有权
2. 设计真实领域表结构
3. 替换默认履约逻辑
4. 决定是否需要认证、权限、限流和审计
5. 编写项目自己的首页、文案、国际化和法务页面
6. 为实际商品取得支付提供商的业务批准
7. 配置独立的商品、密钥和 Webhook，不能跨项目共用
