## Design Context

### Users

The primary users are operators and administrators of small SaaS products. They use the admin console to scan system health, find users, review subscriptions and payments, recover failed webhooks or emails, maintain plans and settings, and inspect audit history. The interface should favor fast scanning, predictable actions, and dense but readable operational data.

### Brand Personality

Calm, capable, and trustworthy. The product should feel like a carefully built independent SaaS foundation. Public pages use a near-black background, red accent, Manrope body type, and locally hosted Big Shoulders display type, following the reference supplied by the creator on 2026-10-20: https://bulin47ai.com/bulin-47-ai-trend. The admin console retains its warm neutral palette, terracotta accent, and Bricolage Grotesque display type.

### Aesthetic Direction

Public pages use large condensed uppercase headings, off-white and red typography, restrained red ambient light, fine borders, numbered sections, and two offset portrait previews. Keep the SaaS content and existing product actions. Default to dark while retaining saved preferences and a complete light theme. The admin console remains an operational workspace with persistent sidebar navigation, a compact utility header, clear page titles, and readable data tables.

Public pages also offer an Ozil template, based on the creator's reference https://tryozilgoalai.com/ supplied on 2026-10-20. It uses a warm off-white background, cobalt blue actions, orange labels, inclined condensed headings, three overlapping portrait previews, and a full-width blue feature strip. It defaults to light and supports dark. Keep the classic template available, remember each template's theme separately, reuse existing product behavior and localization, and scope the new styling away from the admin console.

### Design Principles

1. Put navigation and system context in a stable sidebar so operational content receives the full page width.
2. Make status, failures, and actions easy to scan without turning every datum into a decorative card.
3. Preserve existing API, authorization, routing, localization, and frontend behavior while changing presentation.
4. Use the public red and black palette with restrained borders and motion; preserve the admin console's warm palette.
5. Adapt the workspace for mobile with an accessible compact navigation pattern and no loss of critical actions.
